## Q1〜Q6: 必ず聞く質問 (20 分、優先度順)

### Q1: 利用規約 §9-10 の責任制限条項の実効性 (3 分)

```
利用規約 §9 のサービス保証 disclaimer と §10 の損害賠償上限
条項について、消費者契約法 8〜10 条との関係でお伺いいたします。

§9 では「軽過失の場合のみ免責される」「故意又は重大な過失による
場合を除く」を明記しております。
§10 では損害賠償上限を「個別の移行注文に対して支払われた金額
を上限とする」とした上で、同様の故意・重過失除外を明記しております。

これらの条項について、

(a) 消費者契約法 8 条 1 項 1 号 (全部免除無効) との関係で、
    現状の文言で実効性は確保できているでしょうか
(b) 消費者契約法 10 条 (信義則違反による無効) のリスクを
    減らすために追加すべき表現はありますか
(c) 上限額を「過去 12 ヶ月の支払額」に変更する案も検討しましたが、
    本サービスは一回課金なので「個別注文の支払額」のままで
    妥当でしょうか
```

### Q2: プライバシーポリシー §3 の越境提供記述の APPI 適合性 (3 分)

```
プライバシーポリシー §3 で 6 社の subprocessor (Anthropic, GitHub,
Stripe, Cloudflare, Fly.io, Resend) を列挙し、APPI 27 条 5 項 1 号
の「委託」位置付け + 28 条 越境提供の枠組みで整理しております。
各 subprocessor について「所在国」「個人情報保護制度の概要」
「保護措置」の 3 項目を表で記載しております。

これらの記述について、

(a) PPC ガイドライン (規則 17 条) で求められる項目を網羅できて
    いるでしょうか
(b) 「米国は包括的個人情報保護法を有していない」「Anthropic は
    SCC 相当の契約条項を提供」等の私の記述に、法的に不正確な
    部分はあるでしょうか
(c) 顧客の同意を「サービス利用 = 同意」の黙示同意に依拠している
    のは十分でしょうか。明示的な同意 UI を Stripe Checkout 前段に
    設ける必要がありますか
```

### Q3: 米ドル建て日本居住者販売の準拠法・国際裁判管轄 (3 分)

```
利用規約 §13 で準拠法を日本法、Tokyo 地方裁判所を非専属管轄と
しております。日本居住消費者については民訴法 3 条の 4 (消費者
住所地裁判所への提訴権) を明示的に保護する文言を追加しております。

(a) 米ドル建てで主に英語圏顧客に販売する形態で、日本法を
    準拠法に固定するのは現実的でしょうか
(b) 米国・カナダ・オーストラリア等の顧客から訴訟が来た場合、
    現実的にはどう対処すべきでしょうか
(c) 「日本法に対し各国の消費者保護法が部分的に強行適用される」
    と理解していますが、実務上どう備えればよいですか
```

### Q4: 返金ポリシー §2A 契約不適合カーブアウト (3 分)

```
返金ポリシー §2A で、消費者契約法 8 条/8 条の 2/9 条/10 条の
カーブアウトと、民法 562-564 (契約不適合責任) に基づく代金減額・
履行追完・解除権を明示的に保護する文言を追加しております。

これは独立 review (別 AI による review) で「§2 の 『PR 完成後は
返金不可』が消費者契約法 8 条の 2 で無効化される可能性がある」
との指摘を受けて追加した条項です。

(a) この §2A の記述で、消費者契約法上のリスクは概ね対処
    できているでしょうか
(b) 「契約不適合」の判断基準が文書上不明瞭です。実務では
    どう対応すべきですか
(c) Refund Policy §3 「部分返金は行わない」も法的に問題が
    ありますか (代金減額請求権は §2A で留保していますが)
```

### Q5: EEA/UK/CH 居住者除外の GDPR 域外性確保 (2 分)

```
GDPR / UK GDPR / Swiss FADP の適用域に当方サービスを引き込まない
ため、ToS §2 で EEA/UK/Switzerland 居住者の利用を明示禁止し、
さらに以下の 3 段防御を実装しております。

1. Stripe Checkout に custom_text で「EEA/UK/CH 居住者は対象外」
   を表示
2. billing_address_collection を required にして billing 国を
   必ず収集 (post-launch で webhook 経由で自動 refund する予定)
3. Landing pricing 末尾に non-availability 注記

(a) これで GDPR 域外性 (territorial scope outside) を主張できる
    でしょうか
(b) 万が一 EEA 居住者が決済通過した場合、即時返金 + 利用拒否で
    対処する運用を文書化していますが、これで GDPR 適用を
    回避できるでしょうか
(c) 万が一 EU DPA から照会が来た場合、現状の準備で適切に
    応答できそうでしょうか
```

## 質問しない (避ける) 内容

- ❌ 「無料でここまで教えてくれてありがとうございます」を繰り返す
  → 1 回で十分。何度も言うと「これ以上は無料では聞けない」と感じさせる
- ❌ 競合他社の名前 (Vercel 等) を持ち出して「彼らはどうしてる?」と聞く
  → 弁護士は他社の機密情報を共有しない
- ❌ 「私の判断は正しいですか?」と yes/no で聞く
  → 「リスク評価」「実効性」「妥当性」 の formulation が良い
