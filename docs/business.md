## §1. ミッション

Next.js の Pages Router → App Router 移行を、可能な限り人手を介さず、
高品質な PR として顧客に届ける SaaS（GitHub App）を開発・運用する。

### §1.1 顧客が体験するフロー

1. Landing page で価格・サンプル動画を確認
2. 「Install on GitHub」から GitHub App をインストール
3. ダッシュボードで対象リポジトリを選択 → 自動見積（ファイル数 → プラン判定）
4. Stripe Checkout で支払い
5. バックエンドが migration job を起動（顧客は閉じてよい）
6. 完了時にメール通知 + GitHub に draft PR が作成されている
7. CI green 確認後、自動で ready for review に昇格
8. 顧客がレビュー・マージ

### §1.2 成功基準（ローンチ後 6 ヶ月）

- **粗利**: 月額 ¥10 万円（≈ $700）以上を 1 人運用で維持
- **完了率**: 受付 job のうち CI green 達成率 80% 以上
- **顧客満足**: PR の reopened 率 20% 未満
- **運用負荷**: operator の手動介入が週あたり 2 時間以下

### §1.3 反成功（やらない・狙わない）

- VC 調達は目的にしない（個人事業として持続可能なら成功）
- 多機能化での競争を狙わない（深い専門性で勝つ）
- 巨大顧客一社依存にならない（1 顧客で粗利の 30% を超えない）

## §2. 市場・競合・前提リスク

### §2.1 市場の現実認識（2026 年 4 月時点）

- App Router は 2023 年 GA、Next.js の既定として定着
- 多くの中規模以上のチームは既に移行完了または進行中
- **残存する Pages Router 採用先**は概ね以下:
  - レガシー保守モード（移行投資の意思決定者がいない）
  - 大規模・複雑なカスタマイズで自動移行が難しい
  - 移行を後回しにしてきた中小チーム ← **本プロジェクトの主戦場**
- 結果として**市場規模は縮小傾向**を前提にする
- だからこそ、専門特化と顧客リスクの肩代わり（返金保証）で勝負する

### §2.2 競合分析

| 区分 | 例 | 弱点（本プロジェクトの差別化点） |
|---|---|---|
| 公式 codemod | `@next/codemod` | 構文変換のみ。semantic な書き換えは非対応 |
| 手動コンサル | フリーランス、エージェンシー | 高額・人材依存・属人的 |
| 汎用 AI コーディング | Cursor / Copilot / Claude Code | 顧客自身が運転する必要がある |
| ノーコード移行ツール | （現存しない） | — |

差別化:
- 顧客は「install → 支払 → レビュー」だけ。**運転責任を負わない**
- semantic な書き換え（`docs/agent.md` §2 参照）に踏み込む
- 失敗時返金で**顧客のリスクを下げる**

### §2.3 主要リスクと対応

| リスク | 確率 | 影響 | 対応 |
|---|---|---|---|
| 残存市場が想定より小さい | 中 | 大 | Phase 0 で市場検証。需要薄なら §5 の横展開先へピボット |
| Anthropic API コスト > 課金額 | 中 | 大 | `docs/operations.md` §2 のコスト上限厳守。超過時は中断・返金 |
| Anthropic API のレート制限 | 中 | 中 | `docs/agent.md` §1.10 で並列度を制限、指数バックオフ |
| Anthropic 利用規約・モデル可用性の変更 | 低 | 中 | 規約・モデル一覧を月次で確認、影響時は本書更新 |
| Next.js 公式が同等機能をリリース | 低〜中 | 中 | 専門性とサポート品質で差別化、価格を下げる |
| 顧客リポジトリの機微情報露出 | 低 | 致命 | `docs/security.md` を厳守 |
| GitHub App 規約・パーミッション仕様変更 | 低 | 大 | 規約変更を継続監視 |

## §3. ターゲット顧客

### §3.1 ICP (Ideal Customer Profile)

- **規模**: エンジニア 5〜50 名
- **業種**: SaaS スタートアップ、社内開発組織、Web 制作会社
- **状態**: Next.js 12〜15 の Pages Router を本番運用、移行を 1 年以上塩漬け
- **痛み**: 移行の優先度は低いが、技術負債として無視できなくなってきた

### §3.2 主要ユーザストーリー

#### US-01: 価格対効果重視のテックリード

> テックリードとして、自社リポジトリの移行を **$249 以下**で済ませ、
> メンバーが本来の機能開発に集中できるようにしたい。

**Acceptance**: Medium プランで完了、レビュー工数が手動移行の 1/5 以下

#### US-02: 副業開発者

> 個人開発者として、副業プロダクトの移行に**1 営業日以内**で着手・完了したい。

**Acceptance**: 支払から PR ready for review までが 24 時間以内

#### US-03: コンプライアンス意識の高い CTO

> CTO として、移行が**コードを学習データとして使われない**ことを保証する
> 明確なポリシーを確認したい。

**Acceptance**: プライバシーポリシーで明示、契約に組み込み可能

#### US-04: レビュー実務担当の開発リーダー

> 開発リーダーとして、生成された PR が**自分でレビュー可能な単位**に
> 構造化されていてほしい（一発巨大 PR は困る）。

**Acceptance**: PR 説明欄に変更概要・要レビュー箇所・未対応事項が
構造化されている（テンプレート → `docs/templates/pr-description.md`）

### §3.3 反 ICP（受けない・歓迎しない顧客）

- monorepo（Phase 5 まで非対応、`docs/operations.md` §2.4 で受付制限）
- 非公開のカスタム webpack/babel 設定に深く依存
- 既に大半が App Router 化済の混在状態
- 業界規制で第三者にコード送信不可（金融・医療・防衛系）

## §4. 収益モデルと財務

### §4.1 課金形態

**pay-per-migration**（1 リポジトリ単位の都度課金）

| プラン | 対象 | 価格(USD) | API コスト想定上限 ⚠暫定 | 想定粗利(USD) |
|---|---|---|---|---|
| Small  | 〜100 ファイル | $99  | $20  | $79 |
| Medium | 〜500 ファイル | $249 | $50  | $199 |
| Large  | 〜2000 ファイル | $499 | $120 | $379 |
| Enterprise | 2000+ または monorepo | 個別見積 | 個別 | 個別 |

⚠ コスト想定値は **Phase 1 (PoC) で実測のうえ Phase 2 までに見直す**。

ファイル数算定: 対象リポジトリ内の `pages/` `components/` 配下の
`.ts/.tsx/.js/.jsx` の合計。実装は `packages/agent/src/sizing.ts`。

#### Phase 1 PoC 実測コストデータ（参考、2026-04-26 時点）

| 検証対象 | pages/ 配下ファイル数 | analyze | migrate | 合計 | 1 ファイルあたり |
|---|---|---|---|---|---|
| 自作 minimal fixture | 4 | $0.0014 | $0.0265 | $0.0279 | $0.0070 |
| `vercel/next.js examples/with-typescript` | 5 | $0.0026 | $0.0461 | $0.0487 | $0.0097 |
| 自作 medium fixture | 31 | $0.0094 | $0.2260 | $0.2354 | $0.0076 |

**観察**:

- 1 ファイルあたり概ね **$0.007〜$0.010** で線形にスケール
- 100 ファイル想定 (Small 上限): **$0.80** (暫定上限 $20 に対し 25 倍マージン)
- 500 ファイル想定 (Medium 上限): **$4.00** (暫定上限 $50 に対し 12 倍マージン)
- 2000 ファイル想定 (Large 上限): **$16.00** (暫定上限 $120 に対し 7.5 倍マージン)

**注意点**:

- Phase 1 PoC 検証は単純パターン中心。複雑な依存・カスタム middleware・
  巨大な Provider chain などはトークン消費が増えうる
- リトライ (Sonnet 失敗時の Opus 1 回) が頻発する repo は 2 倍程度を見込む
- prompt caching は現状の system prompt が短く効いていない (1024 token 未満)。
  実装すれば cache read 9 割で更に削減可能
- 上記実測は 1 回の試行のみ。複数回試行で variance 評価をしていない

**暫定上限の見直しは保留**: 上記の通り暫定値はかなり保守的だが、データ点が
3 件と少なく外れ値リスクの評価が不十分。**Phase 2 で実顧客 repo 5〜10 件分の
データが揃った時点で正式に再評価**する。それまで暫定値は変更しない。

### §4.2 支払い

- Stripe Checkout（カード一括）
- 通貨: USD のみ（日本円は Phase 5 以降）
- インボイス対応: Stripe の自動インボイス機能で代用

### §4.3 完了基準

- 生成 PR の CI（型検査・ビルド・既存テスト）が green
- draft PR が ready for review に自動昇格

### §4.4 返金ポリシー

- 14 日以内に CI green に到達できない場合は**全額返金**
- 顧客側でテストを追加した結果落ちた場合は対象外（Landing で明記）
- 部分返金は実装しない（運用複雑化を避ける）

### §4.5 ユニットエコノミクス

為替前提: 1 USD ≈ ¥150 とする（実数値はランチ時に再確認）。

| 指標 | Small | Medium | Large |
|---|---|---|---|
| 粗利 (USD) | $79 | $199 | $379 |
| 粗利 (JPY 概算) | ¥11,850 | ¥29,850 | ¥56,850 |

**月額粗利 ¥10 万円（≈ $700）達成パス例**:

- Medium 4 件 / 月 → ¥119,400
- Small 6 件 + Medium 2 件 → ¥130,800
- Large 2 件 / 月 → ¥113,700

固定費前提:

- Vercel Hobby: $0
- Cloudflare Workers Paid: $5/mo
- Sentry Team: $26/mo
- ドメイン: $1/mo 換算
- 合計: 約 $35/mo (≈ ¥5,250)

→ 損益分岐は **Medium 0.2 件相当**。固定費は実質無視できる。
本プロジェクトの主リスクは固定費ではなく **API 変動費**。

### §4.6 為替・税

- USD 受領、JPY 課税の構造になるため為替差損益が発生する
- 個人事業の場合は雑所得 or 事業所得で申告
- 取引履歴は Stripe Dashboard と D1 双方に残す

## §5. 横展開先候補（Phase 5 以降）

Phase 0 の市場検証で需要が薄い場合の方向転換先。
JS/TS エコシステム内に絞り、agent の専門性を再利用できる候補のみ。

- **React Router v6 → v7 移行**: 残存市場が大きい
- **Vue 2 → Vue 3 移行**: グローバルでなお巨大
- **Class Components → Hooks 移行**: 古い React コードベース向け
- **Express → Hono / Fastify 移行**: パフォーマンス志向案件
- **Webpack → Vite 移行**: ビルド速度への需要
- **Jest → Vitest 移行**: モノレポ環境向け
- **Redux → Zustand / TanStack Query 移行**: モダン化需要
