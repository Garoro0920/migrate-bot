# ADR-0001: Phase 0 市場検証の方法と判定

> Status: superseded by ADR-0002
> Date: 2026-04-26
> Deciders: operator, agent
>
> **注記**: 2026-04-26 に operator は Phase 0 を skip し Phase 1 に直接着手する判断を下した（ADR-0002 参照）。本 ADR の方針・質問項目・判定基準は将来の市場検証再開時の参照素材として保持する。テンプレート群（`docs/templates/interview-*.md`、`docs/templates/outreach-messages.md`）も同様に保持。

## 文脈 (Context)

`CLAUDE.md` §3 と `docs/roadmap.md` §1.1 に基づき、実装着手前に
Pages Router → App Router 移行 SaaS への有意な需要を確認する必要がある。
需要が薄ければ `docs/business.md` §5 の横展開先候補へピボットする。

制約:
- operator は学生・1 人運用、母集団は学生〜若手の人脈中心
- 全 ICP セグメント網羅は困難なため、量より質で進める
- 1 件あたりのヒアリング負荷は 30 分基準とする

本 ADR は **検証方法・質問・判定基準を事前確定**するために起草される。
結果は本書末尾の「結果」節に追記し、ピボット or Phase 1 着手の判断を最終化する。

## 検討した選択肢 (Options)

### Option A: 5 名の質的ヒアリング（採用）

- 長所: 過去事実とコミットメントを直接確認でき、Mom Test 原則で誤陽性を抑えられる
- 短所: 母集団バイアス、5 名で意思決定する統計的弱さ
- コスト見積: 30 分 × 5〜8 名 + 各 30 分の記録 = 5〜8 時間

### Option B: ランディングページ + 事前登録メール集客

- 長所: 数百規模の弱シグナルが取れる
- 短所: 公開文言の作成コストが高く、Phase 0 で踏むべき手順を Phase 4 に前借りする
- 公開物の作成は憲章 §6（公開文言）に該当し追加合意が必要

### Option C: 既存の SaaS 移行サービスへのアンケート委託

- 長所: 母集団が広い
- 短所: 委託費が予算外、回答品質が検証不能

→ Option A を採用。母集団の偏りは「Strong yes 候補が独立に 3 名以上」で
担保し、偏りが疑わしい場合のみ追加 2〜3 名で補強する。

## 決定 (Decision)

以下の §1〜§4 の方針でヒアリングを行い、§5 の判定基準で
Phase 1 着手 or ピボットを決定する。

---

## §1. ヒアリング対象の選定方針

### §1.1 必須条件（ICP 一致）

- Next.js 12〜15 の **Pages Router を本番運用**している、または直近運用していた
- エンジニア 5〜50 名のチーム、または個人開発オーナー（後者は副次セグメント）
- 移行が 1 年以上塩漬け、もしくはこれから本格検討する状況
- 意思決定または強い影響力を持つロール

### §1.2 除外（反 ICP / `business.md` §3.3）

- monorepo 主体
- カスタム webpack/babel への深い依存
- 既に大半が App Router 化済の混在状態
- 規制業種（金融・医療・防衛）

### §1.3 セグメントの扱い（努力目標）

下表は努力目標であり、**全網羅は必須ではない**。学生ネットワーク前提のため、
入手可能な対象から進める。

| # | セグメント | 対応 US |
|---|---|---|
| A | 中小 SaaS のテックリード | US-01 |
| B | 副業/個人開発者 | US-02 |
| C | コンプライアンス重視の CTO/EM | US-03 |
| D | レビュー実務の開発リーダー | US-04 |
| E | Web 制作会社 / 受託側 | — |

### §1.4 採用チャネル

| 優先 | チャネル |
|---|---|
| ★★★ | 既知の人脈（X / Slack / 学校・勉強会・過去同僚） |
| ★★★ | OSS の maintainer（Pages Router を残す中規模 OSS の committer） |
| ★★ | Next.js Discord / r/nextjs 投稿者 |
| ★★ | 日本コミュニティ（勉強会登壇者、Zenn/Qiita の Pages Router 記事著者） |
| ★ | Wantedly / 求人記述に "Next.js 12/13 Pages" を含む企業 |
| ★ | LinkedIn での "Next.js" + tech lead 検索 |

## §2. ヒアリング設計

- **所要**: 30 分基準、深掘り発生時は最大 45 分で打ち切り
- **形式**: 1 対 1、ビデオ通話または対面、許可があれば録音
- **謝礼**: 無償（明示）。「移行ツール開発のための調査」と告知
- **設計原則**: The Mom Test 準拠。**過去の事実・既出費・コミットメント**を中心に問い、
  製品への意見は最小化

---

## §3. 質問項目（全 18 問）

### §3.1 事前確認 (3 分 / 2 問)

1. 役職・チームのエンジニア人数・自社プロダクトの概要
2. Next.js のバージョン、`pages/` 配下のおおよそのファイル数、monorepo か / 独自ビルド設定があるか（反 ICP 確認を兼ねる）

### §3.2 現状の痛み (8 分 / 4 問) ※過去事実のみ

3. App Router 移行を初めて検討したのはいつか、そのきっかけは何か
4. 過去 12 ヶ月でこの移行に投じた工数・金額は具体的にいくらか
5. Pages Router 由来で困った直近の具体事象を 3 つ、および移行を後回しにしている本当の理由
6. 今後 6 ヶ月で App Router 化が避けられなくなる外的締切はあるか

### §3.3 既存の代替策 (5 分 / 3 問)

7. これまで試した手段（`@next/codemod` / Cursor / Copilot / Claude Code / 外注 / 自前手順）と、それぞれどこで詰まったか
8. 外注見積を取ったことはあるか。あれば金額・期間・断った理由
9. 社内で「自分たちでやる」と決めて止まっている期間は何ヶ月か

### §3.4 ソリューション説明 (3 分 / 質問なし)

60 秒で説明する: GitHub App、install→支払い→PR が届く、CI green まで自動、
14 日以内に green 不達なら全額返金。

### §3.5 反応・価格・コミットメント (8 分 / 4 問)

10. 直感的な懸念は何か（コード送信 / 品質 / レビュー粒度 / 失敗時の対応）
11. このサービスを使うとしたら誰の承認が要るか、経費か個人決済か
12. 価格 **Small $99 / Medium $249 / Large $499** を提示。該当プラン、
    および 高い / 妥当 / 安い の評価とその理由
13. コミットメントテスト（強→弱で打診し最高ランクを記録）:
    - a. リリース時に最初の有料顧客になる、メールで予約のみ
    - b. β 募集枠に登録、連絡先取得
    - c. PoC 完成時にフィードバック提供（無料 or 50% off）
    - d. 公開ローンチ時に教えてほしい（最弱、これだけは「興味あり」とカウントしない）

### §3.6 セキュリティ・法務 (2 分 / 4 問)

14. 自社コードを Anthropic API に送信することは社内承認しうるか
15. 「学習に使われない」契約条項があれば承認が出るか
16. GitHub App 権限（Contents: write / PR: write / Metadata: read）は許容できるか
17. インボイス / 特商法 / 海外送金の制約はあるか

### §3.7 紹介依頼 (1 分 / 1 問)

18. 同じ問題を抱えていそうな知人を 1〜2 名紹介してほしい

## §4. 記録方法

- ヒアリング 1 件ごとに `docs/templates/interview-record.md` をコピーし、
  `docs/decisions/interviews/<YYYY-MM-DD>-<initials>.md` として保存
- 録音可否は事前許可、録音した場合はローカル保管・本書集計後に削除
- 候補リストは `docs/templates/interview-candidates.md` をコピーして
  `docs/decisions/interview-candidates.md`（個人情報を含むため git ignore 検討）
  または手元の表計算で管理

## §5. 判定基準

`roadmap.md` §1.1 の「3 名以上が『ぜひ使いたい』」の運用定義を以下で固定する。
恣意的判定を避けるため事前確定とする。

| ラベル | 条件 |
|---|---|
| **Strong yes** | §3.5 Q13 の **a または b** にその場でコミット。かつ §3.2 で過去 12 ヶ月の投入工数・金額が具体的数値で出る |
| Soft yes | Q13 の c にコミット |
| Vague | d 止まり、または「興味はある」発言のみ |
| No | 価格に明確に拒否 / 反 ICP 該当 / 承認が出ない |

### §5.1 Phase 1 着手条件

- **Strong yes が独立に 3 名以上**（5 名中・追加で集めた場合は累計）

### §5.2 ピボット検討条件

- ヒアリング 5 名以上を達成し、Strong + Soft yes が 1 名以下
- → `business.md` §5 の横展開先のうち上位 2 候補を選び、その領域で Phase 0 を再実行

### §5.3 グレーゾーンの扱い

- Strong yes が 2 名で停滞した場合は、+2〜3 名追加。それでも 3 に届かなければピボット検討。
- 反 ICP の混入が判明したら結果から除外し、母集団を再評価する。

## 結果 (Consequences)

### 短期

- ヒアリング素材一式（本 ADR + 3 テンプレート + アウトリーチ DM）が確定し、
  operator はリスト作成から実施へ即着手できる
- 5〜8 名 × 30〜45 分 + 記録時間 = 概算 5〜10 時間の operator 工数

### 長期

- §5 の判定で Phase 1 着手 or ピボットが確定する
- 結果セクション（下記）の更新時に Status を `accepted` にする

### 後続の判断への影響

- 価格反応が想定と乖離した場合、`business.md` §4.1 の改訂 ADR を別途起こす
- 反 ICP の頻度が高ければ `business.md` §3.3 を更新
