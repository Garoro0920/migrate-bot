# APPI 個人情報開示請求 対応テンプレート

> 日本居住の顧客から個人情報保護法 (APPI) 32〜35 条 に基づく
> 開示・訂正・利用停止・第三者提供停止 請求が来た場合の応答。
>
> Privacy Policy §7 で約束済の対応 (30 日以内応答)。
> Beta 期間中は発生確率低いが、運用ランブックとして整備。

---

## 関連法令

- **APPI 33 条**: 保有個人データの開示請求
- **APPI 34 条**: 保有個人データの訂正・追加・削除請求
- **APPI 35 条**: 利用停止・消去・第三者提供停止請求

請求があった場合、operator (個人情報取扱事業者) は **30 日以内に対応** する義務 (APPI 規則)。

---

## 受信時の判定フロー

1. **本人確認** が最重要。なりすまし対策のため、**本人であることを確認できる情報** を求める:
   - 当社サービス利用時の email アドレス
   - 注文番号 (orders.id) または購入時刻
   - GitHub アカウント名
2. 請求の種類を特定:
   - **開示請求** (33 条): 当社が保有する自分の個人データを見たい
   - **訂正請求** (34 条): 誤った情報を直して
   - **利用停止請求** (35 条 1 項): 個人情報の利用をやめて
   - **第三者提供停止請求** (35 条 4 項): Anthropic 等への提供をやめて
3. **対応可否**: 利用停止・消去は実務的に可能 (DB から削除)、訂正は通常可、ただし契約履行に必要な情報 (会計記録 7 年保管義務等) は除外

## operator が実施する DB 削除コマンド (利用停止請求時)

```powershell
# 該当 customer の削除 (cascade で関連 orders / jobs も削除されない設計に注意)
# 完全削除ではなく、PII 部分のみ匿名化推奨

# 例: customer email を redact
corepack pnpm --filter @migrate-bot/api exec wrangler d1 execute migrate-bot-prod --remote --env=prod --command "UPDATE customers SET email = '[redacted]' WHERE email = '[CUSTOMER_EMAIL]'"

# orders の email 参照は customer_id FK 経由なので追加処理不要
# jobs テーブルは PII 含まず (repo_full_name は public info)
# job_events / refunds テーブルも PII なし
```

⚠ **完全削除 (DELETE) は税務記録保管義務に反するため不可**。
**匿名化** ('[redacted]' に置換) が APPI 35 条と税法の妥協点。

---

## ⚠ 重要な原則

1. **受領後 1 営業日以内に必ず ack** (放置は APPI 違反リスク)
2. **本人確認は厳格に** (なりすまし対応は重大インシデント)
3. **30 日以内回答** は法的義務、超過は PPC 報告事象
4. **微妙な判断は ZeLo 弁護士に相談** (5/12 初回相談済 + 売上発生後の有償 review 想定)
5. **対応記録は別途 incident log に保管** (将来の PPC 検査に備える)
